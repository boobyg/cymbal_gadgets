The Enterprise Dilemma

Why Raw "Text-to-SQL" Fails in Enterprise Production

When Large Language Models are pointed directly at raw data warehouse tables (BigQuery, Snowflake), they consistently produce critical production failures:

Schema Hallucination

LLMs invent column names, query stale staging tables, or misidentify foreign keys, leading to broken syntax or incorrect tables.

Missing Business Logic

Raw database columns do not contain business rules: Does revenue include VAT? Are refunded items deducted? What defines an active account?

Join Fanouts & Duplication

Many-to-many joins produce fanout multiplication traps, resulting in aggregated sales figures inflated by 10x without warnings.

Zero Audit Trail

When a chatbot returns "$12.4M", data engineers cannot verify what filters or table definitions produced the number.

Result: Enterprise teams abandon ungrounded SQL chatbots due to compliance risk. Accuracy < 65% in production
The Architectural Solution

Looker as the Governed Semantic Layer Ground Truth

Instead of querying raw tables, the LLM queries Looker's Governed Semantic Layer (LookML). Looker acts as a deterministic compiler between intent and database execution.

1

Centrally Governed Metrics

Formulas like Gross Margin % or Net Sales are coded once in LookML measures. Every AI query uses the exact same verified formula.

2

Deterministic SQL Compiler

The agent produces a LookML Query Specification (fields, filters, pivots). Looker converts this into dialect-optimized BigQuery SQL with built-in fanout prevention.

3

100% Auditable Reasoning

Every request returns full transparency: agent thoughts, explores searched, query specification, and raw database rows.

Core Takeaway: The LLM never writes raw SQL. The Looker engine writes dialect SQL.

API Architecture

Looker Conversational Analytics (CA) API Family

The CA API in Looker 4.0 provides four key capabilities to build end-to-end conversational data pipelines:

1. Authentication POST /api/4.0/login

Exchanges client credentials (client_id + client_secret) for an ephemeral session token: Authorization: token <access_token>.

2. Agent Definition POST /api/4.0/agents

Configures agent metadata, binds allowed LookML sources (model + explore), and sets persona guardrails via context.instructions.

3. Stateful Sessions POST /api/4.0/conversations

Allocates a server-side session bound to an agent ID. Looker maintains multi-turn message history server-side—no manual token counting!

4. Query Execution POST /conversational_analytics/chat

Submits user prompt + conversation_id. Streams structured reasoning, schema discovery, generated query, and BigQuery data.

Also supports dynamic runtime patching: PATCH /api/4.0/agents/{agent_id}
Payload Transparency

Anatomy of the 5-Stage Agent Response

Unlike generic completion endpoints that return only a text string, Looker CA returns a structured multi-part message stream for complete auditability:

1. THOUGHT
Chain-of-Thought Reasoning: Internal plan detailing how the LLM interpreted the user's intent and selected dimensions.
2. SCHEMA
Explore Introspection: Metadata of LookML views and joins evaluated (e.g. transactions explore).
3. QUERY
LookML Query Specification: Fields (transactions.total_sales_amount), filters, sorts, and limits compiled by the agent.
4. DATA
Verified Tabular BigQuery Results: The exact tabular records returned from BigQuery execution ([{"transactions.total_sales_amount": 1074890772}]).
5. FINAL_RESPONSE
Executive Markdown Summary: Natural language executive answer synthesized directly from the verified tabular data.
🔍 Data Engineering Benefit: Enables building user interfaces with a "Transparency Hub" where business users see the answer and engineers see the SQL audit.
Chronological Pipeline

End-to-End Execution Sequence

Step-by-step lifecycle of an analytical query from prompt submission to BigQuery execution:

1
User Prompt: User asks "What is the total sales amount by store country?"
2
Session Binding: Client passes prompt with conversation_id to POST /conversational_analytics/chat.
3
Semantic Introspection: Looker CA maps intent to Explore transactions, picking dimension store_country & measure total_sales_amount.
4
Dialect SQL Compilation: Looker's modeling engine compiles the field spec into optimized Google BigQuery SQL.
5
BigQuery Execution: Query executes on the analytical warehouse; verified rows returned.
6
Synthesis & Streaming: LLM synthesizes summary adhering to agent guardrails; stream emitted to client.
⚡ Performance: First query caches explore metadata (~15s); follow-up multi-turn queries complete in 2–4s.

Hands-On Phase 4

Step 4: Where & How Guardrails Are Applied in CA APIs

Enterprise governance architecture in Looker Conversational Analytics (CA) APIs:

WHERE Guardrails Are Applied in CA APIs:

  • • 1. context.instructions: JSON payload in POST /agents and PATCH /agents/{id} defining persona, metrics, and tone.
  • • 2. Explore Whitelist in sources: Restricts the agent strictly to authorized models & explores (cymbal_gadgets_boris/transactions).
  • • 3. LookML Modeling Layer: Enforces access grants, hidden fields, and row-level user attribute filters.

HOW Guardrails Are Enforced by CA Engine:

  • • 1. System Prompt Priming: context.instructions are injected into Gemini's internal system prompt before processing.
  • • 2. Metric Steering: Rules force the LLM to choose gross_margin_percentage for profitability queries.
  • • 3. LookML Query Spec (No SQL Injection): Engine emits LookML fields, and Looker compiles SQL—preventing hallucinations.
  • • 4. Output Formatting: Prefix '🌟 Cymbal Executive Summary:' & EUR currency.

Wrap-Up & Best Practices

Key Takeaways for Data Engineers

Core architectural lessons to apply when building conversational data platforms:

1. Never Let LLMs Write Raw SQL

Always ground AI agents in a governed semantic layer (LookML) so business metric calculations remain deterministic, accurate, and consistent across tools.

2. API Explorer as the First Stop

Use Looker's built-in API Explorer to test and validate payloads, inspect parameter schemas, and verify agent behavior before writing application code.

3. Server-Side Context Management

Offload multi-turn conversation state to Looker's /conversations endpoint instead of managing complex context token budgets in application code.

4. Build Auditability In

Always expose thought traces, explore queries, and raw data rows in client UIs to build trust with executive and analytical stakeholders.
