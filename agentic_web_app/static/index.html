End-to-End Query Execution Sequence

1 User Prompt: Question submitted (e.g., "What is total sales by country?").
2 Session Context: Bound to stateful session via POST /conversational_analytics/chat.
3 Semantic Introspection: Agent resolves LookML fields (store_country, total_sales_amount).
4 Dialect SQL Compilation: Looker compiles the formal spec into optimized BigQuery SQL.
5 BigQuery Execution & Audit: Database executes query; verified rows returned with full audit stream.

Task 1

Conversational Analytics API & Creating Your Custom Agent

Typical Conversational Analytics Lifecycle Scenario

When building AI data applications with Looker, your application executes a 3-step sequence:

  1. Create Agent (CreateAgent / POST /agents): Ground the agent in LookML model (cymbal_gadgets_boris), explore (transactions), domain guardrails, and enable analytical details (show_analytical_details: true).
  2. Create Conversation Session (POST /conversations): Looker allocates a stateful server-side thread, managing conversation history and token limits automatically.
  3. Pass Prompt & Query (POST /conversational_analytics/chat): The API generates deterministic BigQuery SQL, executes it, and streams back governed data with a 5-part execution trace.
What We Are Doing & Tracing in the App: In this step, you create your custom agent with show_analytical_details: true. This setting ensures that full execution tracing will be available in the application when prompts are run during Step 3!
Direct Access: CreateAgent Method in Looker API Explorer Open CreateAgent Method

Step-by-Step: How to Run CreateAgent in Conversational Analytics API

  1. Click the Open CreateAgent Method button above (or navigate to ConversationalAnalytics > create_agent).
  2. In the top right, click the Run It tab.
  3. Where to paste the JSON payload: Scroll down to the Request Body editor field labeled body. Clear any placeholder text and paste the JSON payload below into the body editor.
  4. Click the blue Run Request button.
  5. What to expect as an output: The response status will display POST /agents (200: OK) (or 201: Created).
  6. Where to find the newly created agent id: Look at the very top line of the response JSON for the "id" property (e.g., "id": "a9b6933c..."). Copy this 32-character ID!
Multi-Student Naming Rule: Give your agent a unique name (e.g., Cymbal Retail Analytics Agent - Student 42) so you can easily identify your agent among peers on this shared Looker instance.

JSON Payload to Paste into Request Body (body):

{
  "name": "Cymbal Retail Analytics Agent - Student <YOUR_NAME_OR_ID>",
  "description": "Conversational agent for Cymbal Gadgets retail sales & transactions",
  "sources": [
    {
      "model": "cymbal_gadgets_boris",
      "explore": "transactions"
    }
  ],
  "context": {
    "instructions": "- Always use Gross Margin Percentage when asked about profitability, margin, or sales performance.\n- When asked for trends over time, group by transaction date or transaction month.\n- If the user asks for store performance, breakdown by store country.\n- Keep executive summaries concise with key metrics highlighted in bold.",
    "show_analytical_details": true,
    "show_debug": false
  }
}

Task 4

Prompt Tuning, Guardrails & Production Deployment

Data engineers enforce enterprise compliance by tuning agent behavior with strict persona rules using PATCH /api/4.0/agents/{id}.

Cymbal Executive Guardrail Rules:

  • Always begin your answer with '🌟 Cymbal Executive Summary:'
  • Format all currency metrics in EUR with thousands separators
  • Always state gross margin percentages with two decimals
  • Keep explanations concise (under 3 sentences)

Where & How Guardrails Are Applied in Conversational Analytics (CA) APIs

Enterprise AI governance architecture & enforcement mechanisms

WHERE Guardrails Are Applied in CA APIs:

  • 1. context.instructions in API Payload: Applied during agent creation (POST /api/4.0/agents) or tuning (PATCH /api/4.0/agents/{id}). Developers inject natural language constraints, formatting rules, and business KPI definitions directly into the JSON request body.
  • 2. Explore Whitelist in sources: The agent is bound strictly to authorized models and explores (e.g. model: cymbal_gadgets_boris, explore: transactions). The CA API engine rejects queries against unlisted tables, databases, or schemas.
  • 3. LookML Modeling Layer: Field descriptions, dimension groups, hidden fields (hidden: yes), access grants, and user-attribute data filters apply row- and column-level access control before any SQL is generated.

HOW Guardrails Are Enforced by the CA Engine:

  • 1. System Prompt Priming & Grounding: Looker compiles context.instructions into the Gemini model's system-level instructions, enforcing behavior before user queries are parsed.
  • 2. KPI Steering: When an executive asks about "profitability" or "sales health", the rule "Always use Gross Margin Percentage" forces the engine to pick transactions.gross_margin_percentage rather than raw revenue.
  • 3. Deterministic LookML Query Spec (No SQL Injection): The CA engine does not generate raw SQL strings. It generates a structured Looker Query Specification (fields, filters), which Looker's trusted compiler transforms into BigQuery SQL.
  • 4. Response Persona Formatting: Formatting directives (e.g., prefixing with 🌟 Cymbal Executive Summary:, EUR currency formatting, two decimal places) are enforced on the natural language synthesis pass.
