Task 1

Looker API Explorer & Creating Your Conversational Agent

What is the Looker API Explorer? Open API Explorer

The Looker API Explorer is Looker's built-in interactive developer workbench and documentation portal. It gives you instant, in-browser access to browse, inspect, and execute all 400+ endpoints of the Looker 4.0 REST API—including the modern Conversational Analytics suite (/agents, /conversations, and /conversational_analytics/chat). It authenticates directly through your active browser session (no external API keys needed) and generates client SDK code in Python, TypeScript, and Kotlin.

In this task, you'll create a new Conversational Analytics Agent bound to the cymbal_gadgets_boris model and transactions explore.

Scaling to 500 Users: Give your agent a unique name (e.g. append your name or student ID) so you can easily identify your agent among peers on this shared Looker instance.

1. Agent Creation Payload (`POST /api/4.0/agents`):

{
  "name": "Cymbal Retail Analytics Agent - Student <YOUR_NAME_OR_ID>",
  "description": "Conversational agent for Cymbal Gadgets retail sales & transactions",
  "sources": [
    {
      "model": "cymbal_gadgets_boris",
      "explore": "transactions"
    }
  ],
  "context": {
    "instructions": "You are Cymbal Gadgets' Senior Data Analyst. When asked about sales or revenue, use gross margin as the key indicator.",
    "show_analytical_details": true,
    "show_debug": false
  }
}

Task 2

Web Application Architecture & Local Health

In this step, data engineers inspect how client applications interface with Looker. The local service consumes API 4.0 using a dedicated LookerClient wrapper.

Verification via curl:

curl -s http://localhost:8080/api/health | jq .
Cloud Shell Note: Do NOT curl your external Web Preview URL

Run the command with http://localhost:8080 directly in a second Cloud Shell terminal window.

⚠️ Do NOT replace localhost:8080 with your browser's https://*.cloudshell.dev URL. The external Web Preview proxy requires Google SSO login cookies and returns HTML, which results in: jq: parse error: Invalid numeric literal at line 1, column ...

Where do I run this curl command?
  • In a SECOND terminal window in Cloud Shell: Your first terminal is currently busy running ./run.sh. Open a new terminal tab (or click + in Cloud Shell).
  • Inside Cloud Shell (Not your personal laptop): The server is running inside your remote Cloud Shell environment. In that Cloud Shell terminal, localhost:8080 routes directly to the local Python process.
  • Or use the 1-click button below (Fastest!): You don't even need terminal curl—simply click Check my progress below to verify server health directly!
